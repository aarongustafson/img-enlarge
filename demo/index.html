<img-enlarge>

Enlarge an image without changing its link. Read the README for installation and API details.

Read the README View on GitHub esm.sh example unpkg example

Start with one image

Register the component and keep the image’s attributes on the image. The enlarge button appears when the viewer has room to show it larger. Without JavaScript, the image stays in place. Unnamed components open independently. 

<script type="module" src="../define.js"></script>

<img-enlarge>
  <img src="./mountains.svg"
    alt="A trail between two green mountains beneath a golden sun.">
</img-enlarge>

Connect images with a name

Galleries are opt-in. Matching, case-sensitive name values connect images in document order, anywhere on the page. Omit name, or use an empty value, to open only one image. There’s no separate opt-out attribute. Use Previous/Next, arrow keys, or touch scrolling; navigation stops at each end. These image links still work without JavaScript. 

<img-enlarge name="landscapes-and-bikes">
  <figure>
    <a href="./mountains-large.svg">
      <img src="./mountains.svg"
        alt="A trail between two green mountains beneath a golden sun.">
    </a>
    <figcaption>A trail through the mountains.</figcaption>
  </figure>
</img-enlarge>
<img-enlarge name="landscapes-and-bikes"
  caption="A bicycle ready for an afternoon ride.">
  <img src="./bicycle.svg"
    alt="A red bicycle with a basket beside a pale stone path.">
</img-enlarge>

Enlarge only when there is room

The first image fills its reading column. Its control appears only when the viewer can show it larger. Resize the window to compare. The second image uses force to keep the control even when enlargement would not add space. 

<img-enlarge>
  <img src="./mountains.svg" alt="A trail between green mountains.">
</img-enlarge>

<img-enlarge force>
  <img src="./mountains.svg" alt="A trail between green mountains.">
</img-enlarge>

Automatic: the control depends on the available viewer space.

Forced: the control stays available.

Choose the enlarged image

The basic example reuses the original image’s selected source. An enclosing image link takes precedence over that fallback. Responsive images can supply larger candidates without moving their attributes onto the component. Explicit component sources are optional overrides.

Use an existing image link

An image link supplies the larger file without repeating its URL on the component. Image pathname extensions are recognized regardless of query strings or fragments. For an extensionless image URL, add an image MIME hint, such as type="image/jpeg", to the link. Links to ordinary pages aren’t used as image sources. 

<img-enlarge>
  <a href="./mountains-large.svg">
    <img src="./mountains.svg" alt="A trail between green mountains.">
  </a>
</img-enlarge>

Keep responsive candidates on the image

There is no image link or explicit enlargement source here. The thumbnail keeps its own srcset and sizes. When a larger candidate is available and the viewer has room, the component offers enlargement and lets the browser choose a source for the viewer’s measured image width. If the browser already selected the largest candidate, the automatic control stays out of the way; force can override that decision. 

<img-enlarge class="responsive-thumbnail">
  <img src="./mountains.svg?responsive=small"
    srcset="./mountains.svg?responsive=small 800w,
      ./mountains-large.svg?responsive=large 1200w"
    sizes="192px"
    width="800" height="400"
    alt="A trail between green mountains.">
</img-enlarge>

<style>
.responsive-thumbnail > img {
  inline-size: min(100%, 12rem);
}
</style>

Reuse the selected picture branch

A picture keeps its native media and format selection. The viewer reuses candidates only from the branch identified unambiguously by the thumbnail’s currentSrc; it doesn’t mix art-directed crops. 

<img-enlarge class="responsive-thumbnail">
  <picture>
    <source media="(min-width: 40rem)"
      srcset="./mountains.svg?picture=small 800w,
        ./mountains-large.svg?picture=large 1200w" sizes="192px">
    <img src="./mountains.svg" alt="A trail between green mountains.">
  </picture>
</img-enlarge>

Optionally override the enlargement source

Use component-level src only when the viewer needs a different file and can’t use an existing image link. It overrides link and responsive-candidate inference. 

<img-enlarge src="./mountains-large.svg">
  <img src="./mountains.svg" alt="A trail between green mountains.">
</img-enlarge>

Optionally use separate responsive enlargement files

Keep the thumbnail’s responsive attributes on img. Add srcset to the component only when the viewer needs a separate candidate set. These explicit sources override link and candidate inference. A component-level sizes, when provided, describes the viewer, not the thumbnail. 

<img-enlarge src="./mountains-large.svg"
  srcset="./mountains.svg?viewer=small 800w,
    ./mountains-large.svg?viewer=large 1200w">
  <img src="./mountains.svg?thumbnail=small"
    srcset="./mountains.svg?thumbnail=small 800w"
    sizes="192px" alt="A trail between green mountains.">
</img-enlarge>

Source precedence: explicit component sources, then an image link, then inferred responsive candidates, then the original image’s currentSrc or src. The separate space check decides whether to offer a button; it doesn’t choose the file.

Style the light-DOM parts

Use the documented classes and custom properties, not Shadow DOM ::part(). The dialog stays inside its component, so these changes apply only to this example. Here the caption sits beside the image on wide screens, with extra space between them. 

<img-enlarge class="editorial" force
  caption="An afternoon on the mountain trail.">
  <img src="./mountains.svg" alt="A trail through green mountains.">
</img-enlarge>

<style>
.editorial {
  --img-enlarge-dialog-padding: 4rem;
  --img-enlarge-caption-gap: 1.5rem;
}
.editorial .img-enlarge-slide {
  display: grid;
  grid-template-columns: minmax(0, 3fr) minmax(0, 2fr);
  gap: 1.5rem;
  align-items: center;
  text-align: start;
}
@media (max-width: 40rem) {
  .editorial { --img-enlarge-dialog-padding: 3.5rem; }
  .editorial .img-enlarge-slide { grid-template-columns: minmax(0, 1fr); }
}
</style>

A product image gallery

Use JavaScript navigation buttons

Matching name values form a separate collection. These two images use controls="buttons" to request JavaScript-generated Previous/Next buttons, even when the browser supports CSS scroll buttons. Open either image to try them. Single-image collections have no navigation arrows. 

<img-enlarge name="details" controls="buttons">
  <img src="./bicycle.svg" alt="A red bicycle with a basket.">
</img-enlarge>
<img-enlarge name="details" controls="buttons">
  <img src="./bicycle-basket.svg" alt="A woven basket above the front wheel.">
</img-enlarge>

Hide disabled navigation arrows

Set --disabled-button-visibility: hidden to hide the unavailable arrow at either end of the collection. The default is visible. Hiding preserves the control’s space and works with both JavaScript buttons and native CSS scroll buttons. A focused arrow stays visible until focus leaves, so reaching the last image doesn’t make the focused control disappear. 

<img-enlarge class="hide-disabled" name="quiet-arrows">
  <img src="./mountains.svg" alt="A trail between green mountains.">
</img-enlarge>
<img-enlarge class="hide-disabled" name="quiet-arrows">
  <img src="./bicycle.svg" alt="A red bicycle with a basket.">
</img-enlarge>

<style>
.hide-disabled {
  --disabled-button-visibility: hidden;
}
</style>

Translate the controls

An empty data-img-enlarge-config marks page defaults. A value targets the matching gallery name. This configuration applies only to name="french", not the other demos. These images inherit lang="fr-CA": the Canadian French button label overrides the French default, and other controls fall back to French. The first image also overrides its own enlarge label. The opener’s controls stay consistent throughout the collection.

For a single-language page, use a flat label object without language-code keys. See the single-language example. Place configuration before registration. After editing it or changing an inherited language, call refresh() on the affected components. 

<script type="application/json" data-img-enlarge-config="french">
{
  "fr": {
    "open-label": "Agrandir l’image",
    "dialog-label": "Images agrandies",
    "close-label": "Fermer",
    "previous-label": "Image précédente",
    "next-label": "Image suivante",
    "loading-label": "Chargement de l’image",
    "error-label": "Impossible de charger l’image.",
    "retry-label": "Réessayer",
    "position-label": "{current} sur {total}"
  },
  "fr-CA": { "open-label": "Agrandir la photo" }
}
</script>

<div lang="fr-CA">
  <img-enlarge name="french" open-label="Agrandir le paysage">
    <img src="./mountains.svg" alt="Un sentier entre deux montagnes vertes.">
  </img-enlarge>
  <img-enlarge name="french">
    <img src="./bicycle.svg" alt="Un vélo rouge avec un panier.">
  </img-enlarge>
</div>

Recover from a missing enlarged image

This example intentionally points to a missing file. Open it to test recovery; a visible control isn’t a promise that a remote file is available. The component doesn’t make HEAD requests or download enlargement files before opening. The thumbnail remains usable. The dialog reports loading and failure in text, offers a retry, and keeps Close available. The failed image stays visible in a box sized from the thumbnail’s aspect ratio rather than collapsing. The browser supplies its own broken-image indicator and alternative text; the visible error message doesn’t depend on that appearance. No adjacent enlarged images load until visited. 

<img-enlarge src="./missing-image.svg">
  <img src="./mountains.svg" width="800" height="400"
    alt="A trail through green mountains.">
</img-enlarge>

There is no automatic advance, zoom, or pan. Escape closes the modal and returns focus to its opener. esm.sh example · unpkg example. The CDN examples require an npm publication; this local draft does not publish anything.
